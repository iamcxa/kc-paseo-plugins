Project environment settings: design critique

Reviewed 2026-10-22 on main 1adf630, isolated Paseo 0.12.0 daemon, fake op/security/git, fake vault laid out per ADR 0005. Method: design:design-critique, one walk through the whole screen. Screenshots in shots/.

Overall impression

The screen is honest but it is shaped like the code, not the task. Every capability is a row of equal weight in a single long column, so the eye has no starting point and no finish line. Kent's complaint is real: Browse vault sounds like "show me the vault" but it actually changes how every variable row works, from a free-text box to a dropdown, and it does this far below the rows it changes, with nothing on screen saying so. The reference shown on each row is the raw op://vault/item/field path cut off at 260 px. The vault prefix repeats on every row, so the item and field, the only parts that tell rows apart, are the parts that get cut off. Two defects also put work at risk. A layout change throws away the unsaved draft without a word. And a wrong field can read set while its name is hidden by the cut-off.

The walk, as Kent meets it

  1. Add a project: a dropdown labelled "Choose..." (01). The editor opens with Save, Discard and Stop managing already active, for a project that does not exist yet (02).
  2. Connect: six rows: name, a status row whose label changes, token, Save token, Vault. Vault is a text box until a check succeeds, then it becomes a dropdown (02 vs 09). Refusals are clear (05, 06).
  3. Add a variable: type a name in one row, press Add in the next row. The new row turns red at once with "No field picked" and offers a text box for a raw path (12).
  4. Browse vault: a button four rows below. When pressed, every row's text box silently becomes a dropdown (13 to 15). An unreadable item appears as a row inside the variables card and looks like a variable (15).
  5. Pick: a modal list of full paths, in vault order (16).
  6. Test: results land on rows. A deliberately wrong pick (an auth-token variable given the account-SID field) reads set, and the cut-off shows only "TWILIO/TWILIO..." (18).
  7. Fix a failing row: picking a new field for one row wipes every row's result, including an unrelated failure (27 to 28). A full re-Test is the only confirmation (29).
  8. Save closes the editor with no confirmation (19). Stop managing asks first, but the destructive button looks the same as Keep (25).

Findings

#SeverityWhat I sawWhy it fails KentFix
1blocking Browse vault is a hidden mode switch. Before it, each row is a text box that clips mid-path with no ellipsis. After it, each row is a dropdown. The trigger sits below Add, far from the rows it changes, and keeps its label after loading. A button that reads as "look" acts as "change every row". The rows Kent already filled in change kind under his hand. This is exactly his 2026-10-22 complaint. Two ways to set the same value, depending on whether a button was pressed earlier, means two mental models for one field. One control per row, in every state: a field picker that loads the vault the first time it opens. Remove the card-level Browse row. Manual op:// entry becomes a "Type a reference" choice inside the picker.
2blocking The reference hides what tells rows apart. It is 260 px wide, with the vault prefix repeated on every row, then cut off. At 400 px, three different rows read the same "op://.../SENTRY/SENTR..." (m03). A wrong field is hidden by the same cut-off. Kent cannot check his mapping by reading the screen, and the only proof, Test, says set for a wrong field. A mis-mapped secret reaches agents looking correct. Show ITEM › field without the vault, which is already shown once above. Never cut off the field label. Put the full path in a muted second line or a tooltip. Flag "field label differs from variable name" as a soft warning.
3blocking A layout change throws away the draft. Resizing the window across a width between 700 and 800 px returns to the project list. The added row, picks, typed prompt, and an unsaved new project are all lost. It is not a reload: a page marker survived and the daemon saw no new connection. Silent loss of work. It is worse than the r3 "unsaved warning" gap because Kent did nothing to leave. Split-screen, a narrow window or rotating a phone triggers it. Keep the draft and the open project outside the component that the host remounts, for example in a module-level store keyed by root. Restore it when the screen mounts again. Pair this with the leave guard.
4blocking The field picker is a flat list of raw paths. No grouping by item, no search, no mark on fields another variable already uses. The current choice is shown only by text colour. A reference that is not in the vault is placed first and coloured as the current choice, with no "not found". With ADR 0005's layout (one Secure Note per service, label equals variable name) the right answer is nearly always "the field named like this variable". Kent still has to scan every path. A broken reference looks like a valid, selected one. Group by item, show labels only, add search, put the exact label match first as "Suggested", show "used by X", a check mark on the current choice, and "not in vault" in red for a stale reference. Move unreadable items into the picker's footer.
5confusing Adding a variable takes three separated steps. Name in one row, Add in another, then a field elsewhere. The new row is red at once. The layout forces an order, then marks the row as an error for following it. The name is typed by hand even though the field label usually is the name. One "+ Add variable" action opens the picker. Picking a field creates the row, with the name taken from the label and still editable. "Name only" stays as a secondary choice.
6confusing One edit wipes every result. Re-picking one field cleared an unrelated failure on another row. The rule "results match the draft" is right, but applying it to the whole card hides failures Kent has not fixed yet. Clear only the edited row's result. Other rows keep theirs, marked as from the last Test.
7confusing Failures give no next step. "the 1Password field is empty" and "field not found in the vault" sit in red with nothing to press. Kent knows it failed, not what to do. The empty-field fix happens in 1Password, and the screen does not say so. One action per cause: "Pick another field" for not found or outside the vault; "Fill it in 1Password, then Test" for empty; "Check token" for token causes.
8confusing The connection card is six rows of equal weight for a one-time setup. A status shown as a row label; token and its Save on separate rows; Vault changes kind after the check; "1Password service account" is really a Keychain item label. After the first day this card is noise above what Kent edits most. On the first day it reads as a form, not as steps. Once connected, collapse to one line: "● Connected · new-read · demo-dev · Change". When not connected, show numbered steps: name, paste token (check + store in one action), vault.
9confusing Save, Discard and Stop managing are equal siblings at the bottom. Save is enabled with no changes and closes the editor silently. Stop managing shows for an unsaved project. The confirm dialog styles the destructive button like Keep. No dirty state, no success signal, and a destructive action next to the main one. A sticky footer: "3 unsaved changes · Discard · Save". Show a "Saved" toast (useToast is in the plugin kit and unused). Move Stop managing to its own danger section, hide it for an unsaved project, and colour it red.
10confusing Notes posing as rows. An unreadable item ("deploy-key") and import notes appear inside the variables card. They read as variables, or as rows that need an action. Unreadable items go into the picker's footer. The import result becomes a toast.
11polish The Test disclaimer is two sentences of permanent hint, four lines at 400 px (m03). It pushes the content down and is read once. Put Test in the section header (SettingsSection trailing), and the disclaimer behind its info.
12polish Success "set" is muted grey, in the same style as a hint. Paseo's own Providers screen uses a dot plus a word (p02). Success and silence look alike, and the screen does not match the host's style. Use a status dot plus a word: green "set", red "failed: ...", grey "not tested".
13polish The project list shows a count, not health. Paseo's Projects screen uses rows with a chevron (p01). "Add a project" is a dropdown labelled "Choose...". Kent cannot see which project is broken without opening each one. Rows with a chevron: "demo-app · ● 1 of 7 failing at last test". "+ Add project" opens a list.
14polish The placeholder "LINEAR_API_KEY" is close in contrast to real values. In the picker at 400 px, paths wrap as "op://demo-" / "dev/..." (m04). The closing sentence about agents reading values floats unstyled under the cards. These small frictions add to the feeling that the screen is unfinished. Use "e.g. LINEAR_API_KEY". Show labels in the picker, not paths, which removes the wrap. Move the sentence into the variables section's info.

What works

  • Results on each row, never a value. Refusal copy is plain and specific ("Not saved: 1Password rejected the token", the reserved-name reasons).
  • The token is checked before it is stored. Stop managing asks first and states the consequence precisely.
  • One reason per failure class, never raw tool output.

Three directions

  • A. Fix in place (recommended): same page and order; one field picker per row; grouped, searchable picker; one-step add; sticky save footer.
  • A2. Status inside the field pill (revision of A after Kent's 2026-10-22 review).
  • B. Connection line and variable table: connection collapses to a Providers-style status line; variables become a Name / Field / Status table.
  • C. Vault first: the vault is a checklist; a checked field is a variable.
