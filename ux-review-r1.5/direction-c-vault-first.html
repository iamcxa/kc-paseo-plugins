Direction C: vault first

ADR 0005 lays out the vault as one Secure Note per service, with field labels equal to variable names. Given that layout, the vault is the list. Each field is a checkbox; a checked field is a variable, named after its label and renamable. Variables whose field is gone are listed at the top. There is no separate add, browse or pick step. Cost

This is the largest change. The vault must load before the screen is usable, so a slow, rate-limited or partly unreadable vault makes the whole screen fail, not one picker. Field labels that are not valid variable names need a rename step. Variables saved before ADR 0005 become exceptions to manage. Most of it is custom React Native (tree, checkboxes, rename), and it changes what an "add" means in the journey stories. Best fit for Kent's own vault only once it follows the ADR 0005 layout, which has not been checked here.
