Direction B: connection line and variable table

Borrows Paseo's own idiom. On the project list each project is a row with a chevron and a health dot. The Providers screen shows status as a dot plus a word, with an expandable row. The connection becomes one expandable status row. Variables become a table: Name, Field, Status. "+ Add variable" opens the picker first and names the variable from the field label. The project list shows health before you open a project. Static mock.

Cost

The kit has no table, no expandable row and no list-row chevron. The table, the expandable connection row and the list health badge are custom React Native views that must also match Paseo's theme at both widths. The project list needs a cheap health summary, which means storing the last Test result per project or running a test on open; that is a new decision about what the plugin stores. It is closest to Paseo's look, and it costs more than A, mostly in custom layout. What gets worse: more custom UI to keep in step with the host as Paseo changes.
