# 繪圖前的假設

Step A 已先寫入 design/COMMANDER-FIRST.md；以下先於 index.html 與截圖。

- 「Commander」是現有 Comms officer 的主要入口與稱呼；仍由 Captain 決策，代理可做的事與今天相同。自主規劃／派工作者等僅列在設計文件為待裁定提議，不畫成可用功能。
- 打開 Bridge 預設該對話；桌面清單第一張固定入口，手機以同名標題先呈現對話。單一按鈕回來比先回待辦更貼近談方向的用途。
- 手機因此從首頁看待辦、處理閘門多一步；保留 Board 返回以連續換件。不假設方向對話比批准更常用，交由 Captain 評估取捨。
- 原清單分組、件數、圖形加文字的狀態、篩選與詳情寬度不變；通訊官問題移到固定入口並只算一次。沒有問題時入口是導覽，不算待辦。
- 訊息、理由、確認決定與送出／轉送／記錄進度留在本次頁面記憶體；重新載入重置。沿用第八輪的準確擁有者與來源失敗範圍。
- 一步回指揮官適用 Bridge 內深入頁；原生會話與 GitHub 是宿主／外部目的地，不能承諾改變其返回方式。
- 虛構資料可示意現有通訊官詢問、轉述 FO 回答；不示意自動排工作、代准、代驗收或承諾新的能力。查進度只讀既有各件狀態。
- 1440×1000 與 360×780 是靜態提案；手機固定底部按鈕不證明真實手機軟鍵盤。每態順序擷取，fresh profile、file://、無服務與網路。
