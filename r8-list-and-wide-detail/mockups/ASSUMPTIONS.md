# 繪圖前的假設

以 Captain 已接受的 [LIST-AND-DETAIL.md](../design/LIST-AND-DETAIL.md) 為準；以下是設計者的具體選擇，不是新的產品裁決。先寫本檔，再畫稿。

- 外觀沿用前次 round 8 與 round 7 Paseo 擷取：深綠灰底、原生系統字、細分隔線、綠色主要動作，不帶入參考插件的資產或裝飾。
- 桌面 1440×1000 模擬宿主導覽、左側清單及右側寬詳情；手機 360×780 隱藏宿主側欄，一次清單或詳情。桌面訊息送出與決定控制同高 32px，手機所有主要控制至少 44×44px。
- 全部資料虛構：Sample workspace、Demo FO、Review FO、example/demo-project #17；初始共 7 件：權限 1、審查 2、閘門 2、問題 2（含通訊官）。一般通訊官對話入口不多算一件。
- 篩選預設全部，單選既有四類；按 FO 的看法亦保留，分清人數與事項數。來源失敗時用已知下限，不能寫成已完整讀取。每列只有一個主要狀態，種類、等待年齡與關閉分頁是補充。
- 通訊官從清單進入同一詳情；手機先回清單。沒有工作問題時，仍有不計待辦的一般通訊官入口。未分派審查開列直接進該對話並預填，不插入詢問頁。
- 工具權限開列直接示意原生代理會話目的地，離開 Bridge 詳情；不在 Bridge 畫批准或拒絕，也不實際開原生代理。
- 開閘門先看問題與摘要，原文按需展開；對話標明收件人及含其他任務。訊息與決定理由各自獨立；修改與暫緩必填理由，批准可無理由，選完才確認。
- 手機傳訊及決定動作固定在目前可用區域底部，內容可捲動；同時檢查縮短 viewport 的可達性，但沒有實體手機鍵盤證據。
- 確認後留原件；已送出與已轉送仍有原列，已記錄後從待決清單移除。不自動跳件、不自動推進進度；固定示例及擷取工具明確模擬收據。
- 已記錄件「重開」是本次頁面導覽返回之前開過的詳情，先顯示同一決定及理由；不提供歷史清單或原簡報回讀。跨重載原文保存仍是已知缺口。
- 原型以同一文件記憶體保存每件的選擇、理由草稿、訊息草稿及進度；換件、回清單、經通訊官再回來均不得重置。不用 localStorage、sessionStorage、伺服器或資料服務；重新載入固定示例會重置，這是原型限制。
- 所有傳訊、確認、原生及外部連結都只改示意頁內的畫面；不發網路請求、不連 localhost、不啟動 Paseo daemon。審閱頁載入同目錄 PNG，方向問題只有一題。
- 每個狀態有桌面／手機 PNG 和固定 HTML 入口；review.html 左列狀態、右看兩尺寸，可切換、用方向鍵。擷取逐張執行，瀏覽器每個尺寸用全新暫存 profile 並於結束移除。

除上述當次示意記憶體外，不新增資料、保存、歷史、下一件控制、未讀／稍後／執行篩選或權限批准通道。參考授權資訊的更正已在 design/EVIDENCE.md，不重新擴大使用範圍。
