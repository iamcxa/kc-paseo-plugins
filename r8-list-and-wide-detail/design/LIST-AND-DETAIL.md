# 建議：清單留在旁邊，詳情交給正在處理的一件

桌面把 Bridge 交給清單與單件詳情；通訊官也從清單開啟。手機一次看清單或詳情，返回保留原位置。這回應「桌面決定區太窄」，桌面換件由 2 步變 1 步；批准仍 3 步。

**變差：**清單仍分佔閱讀空間，長問題可能更常換行；桌面從清單回通訊官由 3 步增為 4 步，無法同時讀兩個對話。若狹窄時仍強留清單，就會重犯詳情太窄；手機須回清單才能換件。

**待 Captain 判斷：**清單常在、通訊官按件開啟，是否合用？原簡報回讀仍缺；新保存、歷史或來源合併須另案裁定。

## 參考的長處怎麼帶進來

| 長處 | 採用／調整；影響的操作數 |
| --- | --- |
| 快速篩選與件數 | 調整：全部、工具權限、審查、閘門、問題；只算既有事項，問題含通訊官。預設全部，十項基本數字不變；選篩選另加 1，還原全部再加 1。[規則與來源](EVIDENCE.md#參考長處的採用規則) |
| 每列一個主要狀態 | 調整：無法確認優先，其後已結束、待查記錄、轉送進度、待你處理；種類、負責人與關閉分頁只作補充。不合併同 FO 的不同事項，操作數不變。[優先規則](EVIDENCE.md#參考長處的採用規則) |
| 主要動作隨狀態說明 | 調整：問句用「傳給誰」；決定選完用「確認批准／修改／暫緩」；權限用「到原生會話處理權限」。只改既有動作措辭，不加中間一步。[逐態措辭](EVIDENCE.md#詳情的主要動作措辭) |
| 先問句或結果 | 採用：待決先問題與摘要，已記錄先結果與理由，讀不到先說失敗；對話接在後面。開件不多一次點擊。[來源](EVIDENCE.md#參考長處的採用規則) |
| 手機動作固定在底部 | 採用：目前詳情的決定確認與傳訊動作固定在可用區域下緣，鍵盤開啟仍可達，兩者保持分開。點擊數不變，不預估省下幾次滑動。[限制](EVIDENCE.md#參考長處的採用規則) |

## 等待怎麼說、怎麼處理

每列先說要你做什麼，再說種類、負責人與等待時間；詳情明示收件人。[逐態來源與取捨](EVIDENCE.md#bridge-對應與限制)。

| Bridge 狀態 | 清單／詳情先介紹；接著做什麼 | 參考取捨與原因 |
| --- | --- | --- |
| 工具權限請求 | 先說要求允許什麼、哪個 FO 在等；「到原生會話處理權限」直接開該代理原生會話 | 調整：沿用現有去向；不採用參考的原地批准。 |
| 開放閘門 | 問題、摘要、階段及負責人；選結果、理由，再「確認批准／修改／暫緩」 | 調整：保留獨立傳訊與確認。 |
| 已送出／已轉送 | 原列仍在，說明正等轉送或記錄；重開看同一決定進度，不再送一次 | 調整：參考會解釋停下原因；不能把傳送當成記錄。[來源](EVIDENCE.md#bridge-對應與限制) |
| 已記錄／不再開放 | 原詳情先顯示結果及理由，或只說不再開放；停止提供決定；回清單 | 調整：已完成和已讀分開；不加歷史清單，不承諾原簡報可回讀。[來源](EVIDENCE.md#bridge-對應與限制) |
| FO 問題 | 問句、誰在等、等多久；詳情先問句，再說對話含其他任務；傳訊給該 FO | 採用：一句話原因；不借用參考的快捷答覆。[來源](EVIDENCE.md#bridge-對應與限制) |
| 通訊官問題 | 同樣先問句與等待時間；開啟通訊官對話，送出前明示收件人 | 調整：放進同一導覽，不與相似的 FO 問題合併。[來源](EVIDENCE.md#bridge-對應與限制) |
| 已分派審查 | 審什麼、儲存庫與編號、負責人；開列找該 FO，外部審查另開 | 調整：動作名稱對應目的地；不新增 Bridge 內審查或批准。[來源](EVIDENCE.md#bridge-對應與限制) |
| 未分派審查 | 明說缺負責人；開列直接到通訊官並預填詢問，再送出 | 調整：一句話說明下一步；保留既有 2 步路徑。[來源](EVIDENCE.md#bridge-對應與限制) |
| 來源載入／失敗 | 先說哪個來源未完成、清單可能不全；失敗只提供已有的重查或下次檢查資訊 | 採用：未知不能寫成零；對話讀不到也不能叫空對話。[來源](EVIDENCE.md#bridge-對應與限制) |
| FO 分頁已關閉 | 附帶說明分頁關閉，仍保留其待決事項；需回原生對話時明示目的地 | 調整：參考區分未載入／封存；分頁關閉不代表工作結束。[來源](EVIDENCE.md#bridge-對應與限制) |

保留按事項／按 FO 與現行排序；來源未齊只說已知件數。略過需要額外狀態的未讀／稍後／執行中篩選、回執、AI 摘要、統計、排程、聲音及自動封存。

| 讀眼前結果 | 0 | 0 | 0 | 0 |

通訊官：清單入口（建議）回覆 4；詳情內分頁桌面 5；另一個常駐對話桌面 3，但分佔詳情。手機三案均 4；未分派審查都直接開預填對話，維持 2。

**假設與驗收重點：**桌面兩邊都讀得清；換通訊官再回來，選擇、理由與訊息草稿及送出進度不重置。沒有頻率或省時實測；滑動、鍵盤、截斷全文與等待另計。篩選藏住另一件時，先還原再選，桌面換件便是 2 步。
