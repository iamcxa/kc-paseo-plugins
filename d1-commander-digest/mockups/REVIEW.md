# Commander 定期摘要 — 脈絡修訂審查

桌面先開 [review.html](review.html)；手機可單獨開 [review-phone.html](review-phone.html)，全部手機圖片都已內嵌，不依賴相鄰資料夾。這是一個方向，21 個狀態，每態有 1440×1000 與 360×780 PNG，共 42 張；[index.html](index.html) 是無連線的可操作靜態示意。

## 這次改了什麼

Replay（查看這點的來龍去脈）先交代 Commander 自述的三行：這件事、之前發生、現在需要你。每行有自己的精確 FO（專案執行負責人）來源連結，按下便定位該則。原文不再是孤立句子，而是放在它自己的 FO 對話中，突出引用那一則，保留前後角色、時間和順序；更早／更後只擴展同一段對話。

切換點時來源由點本身綁定，預約、匯入及試用各有自己的來源、脈絡及 FO。多份長來源也各自顯示該點同一 FO 的對話範圍，不把另一個 FO 的內容當作前後對話。前後文缺失或脈絡無來源就明說，沒有用鄰接訊息推論原因；對話訊息也不擅自標成 Captain 的話。

三個主要出口仍是開啟 FO、繼續討論、回覆新決定。手機內文獨立捲動，三個出口固定可見。回覆時保留摘要點識別及原句，與 Captain 自己的文字分開；一般方向仍可直接輸入後送出。具名關卡、完整說明、選擇、Confirm（再次確認後送出）、必填原因與防重送均不變。送出、轉交、已記錄仍分開顯示，不靠計時器自動推進。

所有人物、任務、脈絡、對話、時間、方向與決定均虛構。此頁不發送訊息、不記錄關卡、不接 daemon，也沒有新增產品模式、篩選器、各 FO 計數或推測歸屬。新增收集成本的量測方法與未測量限制在 [EVIDENCE.md](../design/EVIDENCE.md)，使用者操作模型在 [DIGEST.md](../design/DIGEST.md)。

## 看圖與操作

審查頁左側選狀態，右側看桌面／手機，可切尺寸、按左右方向鍵換狀態，點圖看原尺寸；每頁只有一個方向問題。手機單檔使用原生狀態選單與前後按鈕，圖片全用 data: URI，能從獨立資料夾開啟。圖稿內一般回覆只有明確按送出才增加虛構訊息，Confirm 也只改離線示意。

| 狀態 | 判斷重點 |
| --- | --- |
| 先讀這輪摘要 | 三點由 Commander 改寫；研究 FO 沒有回報，明示未知。 |
| 看這句的原文 | 三行前因後果各有精確來源，原文留在同一 FO 的前後對話中。 |
| 長原文與多份來源 | 同一點的多份長來源各有自己的同 FO 對話範圍，三個出口固定。 |
| 長原文：捲到最後 | 捲到底仍可看原文所在對話、擴展前後及使用三個出口。 |
| 預約這點的脈絡 | 只顯示預約 FO 的來源、脈絡與前後對話。 |
| 匯入這點的脈絡 | 只顯示匯入 FO 的來源；現在需要先確認日期欄位。 |
| 更早與更後的對話 | 擴展同一試用 FO 對話，沒有混入其他 FO 或猜測因果。 |
| 原文找不到 | 不拿相似文字補上，明示不可用；仍可開 FO。 |
| 開啟 FO | 只示意進入指定 FO 與返回 Commander，未測宿主。 |
| 留在 Commander 討論 | 原句作可移除上下文，草稿未送出。 |
| 回覆後，引用仍保留 | 摘要點識別與原句隨訊息保留，與使用者自己的文字分開。 |
| 一般方向：直接輸入 | 不開 Replay，輸入後按送出。 |
| 一般方向：按送出後 | 虛構使用者訊息只代表本機示意；沒有關卡目標或記錄。 |
| 從原句回覆新決定 | 先回 Commander，尚未指定關卡；須另按具名入口。 |
| 按具名關卡，讀說明 | 目標為試用 FO／預約流程／驗證，不能由摘要來源推定。 |
| 選擇後，再次確認 | 選准仍未送出；須按 Confirm。 |
| 修改需要原因 | 尚未輸入原因，Confirm 不可用；暫緩同理。 |
| 填原因後，等待確認 | 原因屬這個具名關卡；尚未送出。 |
| 確認後，尚未記錄 | 送出／轉交／已記錄保持分開，不畫成自動完成。 |
| 已轉交，尚未記錄 | 具名入口與重新開啟的詳情保留相同決定及進度。 |
| 已記錄，重開不重送 | 保留原決定，沒有第二個 Confirm；不代表工作已全部完成。 |

檔名、尺寸與 SHA-256 在 [artifacts.json](artifacts.json)。短 Replay 先看三行，往下捲才讀原文前後文；「更早與更後」狀態把引用移到可見區，方便直接看前後來回。長文起點與真正底部兩態用來檢查三個出口是否仍可見。沒有把捲動或閱讀成本藏進一個點按的數字。

## 已檢查的範圍

最新結果在 [checks/tests.json](checks/tests.json)、[checks/capture-evidence.json](checks/capture-evidence.json) 與 [capture.log](capture.log)。證據綁定最終 HTML、桌面審查頁與手機單檔的雜湊；記錄每態實際視窗及按鈕幾何、圖片原尺寸、全新瀏覽器及清理結果。實際命令在 [checks/commands.json](checks/commands.json)。

來源路由先在舊稿重現：[checks/cycle-5-routing-before.json](checks/cycle-5-routing-before.json) 顯示從長卡返回後，預約點仍出現試用來源。新檢查則從長卡切換每一點，核對點識別、所有來源和 FO；三行來源各自定位精確訊息；前後擴展保留同 FO 序號及原角色。其餘草稿、焦點、引用保留、具名關卡及重開防重送的檢查繼續保留。

桌面審查頁在全新 Chromium 由 file:// 載入多個狀態的桌面／手機圖片，檢查 naturalWidth、naturalHeight、尺寸切換與方向鍵。手機單檔另複製到一個沒有其他檔案的自建資料夾，於全新 360×780 Chromium 開啟，核對三個修訂狀態的內嵌 PNG；沒有圖片資料夾或網路依賴。自建瀏覽器、空白 profile 與單檔驗證資料夾全部清理，不碰使用者瀏覽器資料。

這只驗證離線圖稿、原型資料關係與瀏覽器呈現；不能證明模型改寫忠實、真實前後文完整性、伺服器游標、來源保留期、發送、關卡記錄、宿主、實體手機或軟鍵盤。來源契約另有 [context-window.json](../design/checks/context-window.json) 的假傳輸探針，也不是真實 daemon 驗收。

套件檢查記 [checks/package-checks.json](checks/package-checks.json)：既有 design_surfaces 欄位缺口依派工記 SKIPPED，roborev 未跑，沒有產品程式或工作流程規則變更。這些檢查不取代 Captain 或設計總監的審查。

## 仍待決定

只讀既有回報、不催問 FO 已確認。頻率、成本上限與現有 Commander 如何採用新指示仍待 Captain；本次沒有測得新增 token 或金額，也沒有啟用。設計原文與證據已同步本次脈絡需求，這份離線提案待審。

使用 Node.js 執行本目錄 capture.mjs，第一參數傳 Chromium 的完整執行檔路徑，會順序擷取 PNG、重建內嵌圖片的手機頁並驗證。程式只用 Node.js 內建模組，沒有 localhost 服務；使用瀏覽器偵錯管線，不監聽網路埠。
