# 繪圖前的假設

本檔先於 HTML 與截圖建立。依第二次審查通過的 Step A，以及派工已確認的只讀收集策略製作；不重開收集策略的選擇，也不設定頻率、成本上限或現有 Commander 指示的套用方法。

- 只讀 FO（專案執行負責人）的既有回報；沒有回報標未知，永不催問。所有角色、專案、時間、回報、關卡、方向與決定文字完全虛構；不引用真實 Captain 或代理對話。
- 使用指定 round-9 的 commander-home、gate-open 及 decision-reason-typed 實際截圖為視覺基準，並參考 r9-commander-first 的既有圖稿。保留深色背景、細分隔線、綠色 Commander 入口、左清單／右對話、固定輸入框與手機單頁；宿主側欄恢復基準的 320 px。依本次硬性範圍移除篩選器、模式和各 FO 計數，不復刻舊樣例資料。
- 閱讀方式是 Commander 自述的摘要及每點 Replay（查看這點的來龍去脈）。收集時間可見，已更新／受阻／等你決定以短文字區分；無回報的 FO 只有未知行，不捏造可引用訊息。
- Replay 桌面置中卡，手機從底部展開；先呈現原句與 Commander 自己的三行前因後果，每行有自己的精確原文連結。下方把引用放在它自己 FO 的時間線中，先顯示前後各兩則，保留角色及時間，可明確按更早／更後擴展。來源遺失就明說，不補因果；仍能開該 FO。三個主要出口仍為開啟 FO、繼續討論、回覆新決定，固定可見。
- 後兩個出口只關閉卡片、回 Commander 輸入框，附上可移除的這句上下文，不自動發訊、不清除既有草稿、不預選關卡。明確送出後，訊息保留該摘要點的識別及原句，以引用區與 Captain 自己的文字分開呈現；清空草稿不刪除已送訊息的引用。一般方向可直接輸入後按送出，共兩個操作；摘要與 Replay 不是前置條件。
- 關卡目標只由使用者按具名入口指定。入口標出 FO、任務與階段；閱讀完整說明後才能選擇及 Confirm（再次確認後送出）。要求修改與暫緩必須有原因。確認後入口改顯示送出／轉交／已記錄的目前進度，不再等待 Captain；重開保留選擇、原因與進度，不能重複 Confirm。後續進度僅用虛構狀態分別示意，不以計時器自動推進；沒有內嵌權限批准。
- 手機在 Commander 對話的輸入框上方顯示具名關卡入口，桌面沿用左清單入口，避免為這張摘要新增關卡配對。從 Replay 回覆新決定後仍須按它；只有一個關卡也不省略。
- 原生 FO 對話的開啟在此以本機詳情示意，保留返回 Commander 的路徑；不聲稱測到宿主導覽或真實回傳。靜態頁面內的送出只在明確點擊後新增虛構訊息，不連線、不存儲、不設定排程。
- 每態擷取 1440×1000 與 360×780；手機是真實視窗尺寸的 Chromium 呈現，不是實體手機、軟鍵盤或原生 sheet 的驗收。同一點包含長原文與多份來源的起點／捲到底狀態；脈絡及原文內文獨立捲動，三個出口固定可見。圖稿每點有自己的 FO 與精確來源，多份來源也只讀該點自己的 FO 時間線；沒有全域長文旗標把其他點的來源帶進來。必要時內文可捲，操作與返回不可掉出可見區域。
- 審查頁使用本機相對 PNG 路徑，左狀態／右桌面及手機，提供尺寸切換與左右方向鍵；頂部只問一個方向問題。審查頁的尺寸切換不屬於產品模式。另建單檔 review-phone.html，內嵌全部手機 PNG，可在沒有相鄰圖片資料夾時開啟；不因此宣稱已測實體手機。
- 截圖只開本任務自有 HTML：file://、全新空白 profile、headless Chromium、一次一個瀏覽器及一次一張截圖，無 localhost 服務、不碰 Paseo daemon。擷取後關閉自建瀏覽器，移除本次自建空白 profile；不碰使用者瀏覽器資料。

## 交付界線

這是單一方向的離線視覺與互動提案。可驗證本機畫面、出口、草稿／焦點與關卡原因要求；不能證明產品已實作、模型忠實改寫、真實原文讀取、真實訊息／決定送達、記錄、宿主或手機行為。設計總監與 Captain 仍有審查權。

## 脈絡修訂的界線

脈絡三行分別說明範圍、先前經過、目前需要及明說的影響，不能因相鄰便推定因果。對話中的 user 訊息只顯示為對話訊息，不擅自標成 Captain。原文連結定位該行的精確來源，擴展只讀同一 FO；這些只讀動作不自動請 Commander 重寫或催問 FO。新增模型用量與金額均未量測。
