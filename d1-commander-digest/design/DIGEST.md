# Commander 定期摘要 — Step A

建議：定時讀取各 FO（專案執行負責人）的既有回報，由 Commander（統籌對話的代理）換句話說；每點只有一個 Replay（查看這句的來源）。這是待審設計，沒有啟用排程或改動代理。

## 先看什麼，何時看細節

Commander 對話內，每輪只有收集時間及幾句有變化、受阻或待決定的重點；不貼原文，不加篩選器、模式或各 FO 計數。沒有變化便不新增摘要；無法收集時保留上一輪時間並明示失敗，不能當作沒有變化。讀取成功但缺回報時，說「尚無可確認的新回報」，不寫成進度完成。

虛構例：Commander 寫「預約流程已修好，現在等你安排試用。」點 Replay，才看到同一句及虛構 FO 原文「預約流程修正完成；試用時間待安排」。原文旁標 FO、回報時間及「開啟 FO」；跨 FO 的一句須列出全部來源。這些句子完全虛構，不代表任何真實專案。

Replay 是一張可關閉的卡，手機由下方展開。卡內依序是這句、原文、三個動作：「開啟 FO」「繼續討論」「回覆新決定」。後兩者關閉卡，回到原 Commander 輸入框，帶著可移除的這句上下文；不複製整段原文進輸入框，不自動送出，也不替你選關卡。

一般方向直接在 Commander 輸入、送出即可，不必先開 Replay。要作關卡決定，必須另按有名稱的關卡、閱讀它的完整說明，再選決定並按 Confirm（再次確認後送出）。即使只有一個關卡也要明確點選；摘要的來源只能查證原話，不能指定決定目標。

## 五件事與操作數

起點：已開啟 Commander，摘要、輸入框及具名關卡入口可見；每次點按、一次輸入文字、一次送出各算一個操作，閱讀與系統載入不算；需捲動或另開入口時另加。數字是設計推演，尚未做操作測量。

| 目的 | 最短操作 | 從摘要累計 |
| --- | --- | --- |
| 讀摘要 | 直接讀 | 0 |
| 看這點的 Replay | 點 Replay | 1 |
| 開 FO 對話 | Replay → 開啟該 FO | 2 |
| 留在 Commander 討論 | Replay → 繼續討論 → 輸入 → 送出 | 4 |
| 回覆一般方向，最短路徑 | 輸入 → 送出 | 2；不經 Replay |
| 帶著這點回覆一般方向 | Replay → 回覆新決定 → 輸入 → 送出 | 4；可選 |
| 從這點作關卡決定 | Replay → 回覆新決定 → 按具名關卡 → 閱讀說明 → 選決定 → Confirm | 5；閱讀不計次 |
| 同上，須填原因 | 上述路徑，在 Confirm 前輸入原因 | 6 |

「要求修改／暫緩」必須填原因。關卡決定也可直接從具名關卡入口開始，不必經過 Replay；讀完整說明、選決定與 Confirm 不能略過。多個 FO 各有自己的開啟連結，不自動挑一個。返回卡或關閉卡恢復原點與焦點；草稿保留，既有草稿不被覆蓋。

## 收集方式與來源

建議沿用 Bridge（Paseo 與工作流程的連接外掛）的定時檢查方式，每輪讀各 FO 已有回報，再由 Commander 改寫。只讀回報不喚醒 FO；現有逐字轉述的行為需要另經批准才能改變。

每句都能顯示它的精確原文；找不到時就明說。來源失效不換成相似文字，也不假裝已驗證；仍可開啟 FO 對話。技術依據、排程比較與驗證限制放在 [EVIDENCE.md](EVIDENCE.md)。

## 成本、退步與待決事項

**本次未測得一次收集的模型用量或金額。** 只讀 FO 回報仍有 Commander 閱讀與改寫的成本，不能稱免費；量測方法見證據文件。

代價：批次會延遲消息；只讀可能漏掉未寫入回報的進度；改寫可能失真；Commander 對話變長也會增加成本。跨來源的一句會有較長 Replay；摘要不是當前關卡狀態，也不能替 Captain 批准權限。

先請 Captain 決定收集策略：是否接受「只讀既有回報，缺資料標未知，不自動催問」？頻率與成本上限須在程式實作前依量測另定，現在不預設啟用值。現有 Commander 不會自動換用新指示，套用方法也須另核准；不能直接重建或改動正在使用的對話。

關卡仍以你明確選取並確認的關卡說明為準，原話轉交 FO 記錄；送出、轉交、已記錄三者仍分開顯示。Step A 修訂後待設計總監複審；尚未開始 Step B 圖稿，也未取得 Captain 對本提案的回答。
