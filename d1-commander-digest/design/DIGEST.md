# Commander 定期摘要 — 脈絡修訂

每點 Replay（查看這點的來龍去脈）先由 Commander（統籌對話的代理）說明前因後果，再讓你核對 FO（專案執行負責人）原文所在的對話。這是依本次審查修訂的離線設計，尚未啟用。

## 摘要先說重點，Replay 再交代脈絡

Commander 主對話每輪只有收集時間，以及已更新、受阻或待決定的重點；不貼原文、不加篩選器、模式或各 FO 計數。缺回報就標未知，收集失敗不當作沒有變化。已確認採只讀既有回報，不催問 FO；頻率與成本上限仍待決定。

點開一點，先看 Commander 用自己的話寫的三行：

- **這件事**：在做什麼、這次範圍到哪裡。
- **之前發生**：先前發生了什麼，為什麼走到目前這一步。
- **現在需要你**：在等你的什麼意見或決定，已有回報明說的後續影響。

每行都有自己的精確原文連結。找不到依據就明說「這部分尚無可確認的回報」，不因兩則訊息相鄰便推定因果，也不代替 FO 補上未說明的影響。

虛構例：這件事是預約流程的範例團隊試用；先前清單缺少取消步驟，現在已補齊；目前要你決定是否開始試用，若暫緩便不開始。這三行各引用不同的虛構 FO 回報，不是把一段問題當作全部背景。

## 原文放回它自己的對話

三行脈絡下面，顯示引用原文前後各兩則既有時間線內容，保留角色、時間和順序，並突出引用的那一則。只讀該原文所屬 FO 的對話；多份來源分開呈現各自的對話範圍，不把不同 FO 混成一段來回。原時間線的對話訊息不擅自標成 Captain 的話。

「更早的對話／更後的對話」每次擴展同一段對話，不切模式。點某行脈絡的原文連結，會定位到它所引用的精確訊息；若不在目前範圍，就載入該位置。來源、前段或後段取不到時分別明說，不能拿相似文字補上。看到前後文仍不代表已確認因果或已取得決策權。

卡片仍只有三個主要出口：**開啟 FO、繼續討論、回覆新決定**。手機內文可捲，三個出口固定可見。後兩個出口回 Commander 輸入框，保留可移除的這點上下文；按送出後，引用和你自己的文字分開保留，不自動發訊，也不預選關卡。

## 操作數與理解界線

起點：Commander、摘要、輸入框及具名關卡入口可見。點按、一次整段輸入、送出各算一次；閱讀不算，捲動另加。以下是設計推演，不是理解能力、閱讀時間或真人驗收。

| 目的 | 最短路徑 | 次數 |
| --- | --- | --- |
| 讀摘要 | 直接讀 | 0 |
| 理解一點的來龍去脈 | Replay → 讀三行與原文前後文 | 1，加實際捲動 |
| 核對一行脈絡 | 上述路徑 → 該行的原文連結 | 2，加實際捲動 |
| 再往前或往後看 | 已開 Replay → 更早或更後 | 每次另加 1 |
| 開 FO | Replay → 開啟 FO | 2；多個明確目標時另計選擇 |
| 留在 Commander 討論或給方向 | Replay → 選回覆出口 → 輸入 → 送出 | 4 |
| 一般方向，不看 Replay | 輸入 → 送出 | 2 |
| 理解後作關卡決定 | Replay → 回覆新決定 → 按具名關卡 → 讀完整說明 → 選擇 → Confirm | 5；須原因為 6 |

若要多核對一行或擴展對話，上述決定路徑逐次加 1；原文很長就另計捲動。資料是否足以給意見，由你判斷；來源缺失時不能聲稱已提供足夠脈絡。

即使只有一個關卡，也必須按它的名稱、讀完整說明，再選擇及 Confirm（再次確認後送出）。要求修改／暫緩須填原因。送出、轉交、已記錄仍分開顯示；重開保留決定，不容第二次確認。摘要點與脈絡來源都不指定關卡目標，也不批准代理權限。

## 新增成本與代價

**新增的模型用量與金額都未量測。** Commander 現在要讀可支持三行脈絡的既有訊息，並多寫三行及來源，因此收集時的輸入、輸出和來源驗證會增加；不能只計摘要字數。前後對話與「更早／更後」可在打開時按需讀取，不因此喚醒 FO，也不自動要求 Commander 重寫。

同一訊息被多點引用時共用讀取結果，先限制讀取範圍；不足便標未知，不能為填滿背景無限翻歷史。量測須分開記錄收集新增的訊息／位元組、Commander 用量，以及打開或擴展 Replay 的讀取量；方法與精確來源契約在 [EVIDENCE.md](EVIDENCE.md)。

代價是卡片更長、手機需要更多捲動；前後文可能仍不足、或已出現收集之後的新回報，必須標清時間，不能悄悄改寫原摘要。現有 Commander 採用新指示的方法、頻率與成本上限仍須批准。此稿與圖稿待審，沒有產品、代理或排程變更。
