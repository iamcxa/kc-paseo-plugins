# Paseo 0.13.2 and plugins: what is new vs 0.13.0 (read 2026-10-28)

## Conclusion

0.13.1 and 0.13.2 exist and bring nothing for plugins. Both are bug-fix releases (an app startup crash; Android animation fixes). The plugin package `@getpaseo/plugin` at 0.13.0, 0.13.1 and 0.13.2 is byte-identical except for version numbers (`diff -rq` on the three tarballs, 2026-10-28). Everything plugin-related that your plugins care about arrived in 0.13.0 (already on this Mac) or is in the 0.14.0 beta (not on stable). Nothing in 0.13.x breaks either plugin. No host feature in 0.13.x or 0.14.0-beta.1 gives plugins sub-routes, hides the host-drawn "Back to plugins" line, or lets `useRpc` take a per-call timeout.

## 1. Versions and dates

- Newest stable: **0.13.2**, GitHub release 2026-10-26 12:54 UTC, marked "Latest". 0.13.1 was 2026-10-26 06:33 UTC. 0.13.0 was 2026-10-24. Source: `gh release list -R getpaseo/paseo`, https://github.com/getpaseo/paseo/releases
- Newest overall: **0.14.0-beta.1**, pre-release, 2026-10-27 (same source; npm `@getpaseo/plugin` time field agrees).
- 0.13.1 notes: one fix, a startup crash with "Show background" and 8+ workspaces in a project. 0.13.2 notes: four Android animation/bottom-sheet fixes. Neither has a "Plugins" section. Source: `gh release view v0.13.1 / v0.13.2`.

## 2. Plugin-facing changes

Sources: GitHub release v0.13.0 and v0.14.0-beta.1 bodies; `.d.ts` diff of `@getpaseo/plugin` 0.12.0 vs 0.13.2 and 0.13.2 vs 0.14.0-beta.1 (tarballs in /tmp/pp); live reference https://paseo.sh/docs/plugins/reference.md (fetched 2026-10-28; it already describes the beta, so version notes inside it matter).

**Added in 0.13.0 (stable, already on this Mac)**
- File panels (`addFilePanel`): a plugin opens matching files in the file tab.
- `addAgentPanel`, `useTabState` (per-tab state that survives reload), and shared panel props `workspaceId`, `params`, `revision`, `tab`.
- Plugin translations: `client.i18n`, `defineTranslations`, `useTranslation`; all titles/labels accept translated text. Manifest `translations` and `OVERVIEW.zh-CN.md` for the listing.
- New UI: `Markdown`, `StreamedText`, `Loading`, `DocumentFrame`. Inline SVG or component icons everywhere `icon` is taken.
- Plugin UI imports now live in `@getpaseo/plugin/client/ui`.

**Deprecated / changed in 0.13.0**
- `@getpaseo/plugin/client/react-native` still works but is deprecated; `useRevealedText` there is removed after 2027-04-20 (comment in `react-native.d.ts`).
- Panel props `context` and `agentId`, and `context` on `addWorkspacePanel`, are deprecated; use `params.agentId` and `addAgentPanel`. `SettingsGroup` is deprecated in favour of `SettingsSection`.
- `agent.turn_ended` hook now sends an empty `timeline`; call `timeline.refetch` instead.
- Screens, `openScreen({screenId, params})` and `currentScreen` are unchanged since 0.12.0 (identical in the 0.12.0 and 0.13.2 types). Params ride in the screen URL query; that is the only in-screen routing the docs describe.

**Added in 0.14.0-beta.1 (not stable)**
- `agent.session_open` now also carries `tools` (new `defineAgentTool`), `mcpServers`, read-only `title` and `labels`, in addition to `env`. A plugin can give tools to specific agents; 10-minute tool-call ceiling.
- Plugin builds no longer stall the daemon; a plugin ACP reasoning fix. New provider capability `session.can_stop_runtime` (provider plugins only; idle agent runtimes are released after one hour, resumed on next prompt).
- Not found in any source: new permissions, new RPC timeout controls, screen sub-routes, host settings-screen header control.

## 3. Relevance to the two plugins (/Users/kent/Project/kc-paseo-plugins, read only)

**project-env**
- Nothing in 0.13.2 changes it. It imports `Icon`, `Modal`, `TextInput`, `FlatList`, `useToast` from the deprecated `client/react-native`. Works today; move to `client/ui` before 2027-04-20 (the same symbols exist there). Low risk, no urgency.
- "Back to plugins" line: it comes with `addSettingsScreen`, which Paseo draws. Plugins have had `addScreen` with URL `params` since 0.12.0, and its docs say Paseo owns the header and close action. So params can give back/forward between list and editor states, but I did not test whether a screen drops the "Back to plugins" wording. Treat as an unverified experiment, not a 0.13 feature. No true sub-routes exist anywhere.
- Field picker RPC timeout: I could not find where 30 s comes from. The documented 30 s is the hook timeout. The client default for a plugin RPC is 60 s (`DEFAULT_SESSION_RPC_TIMEOUT_MS` in `@getpaseo/client` 0.13.2 `daemon-client.js`), and `invokePluginRpc` passes no per-call timeout. `useRpc` and `callPluginRpc` have no timeout option in 0.12, 0.13 or the beta. The existing workaround (chunked reads, up to four at once) is still the right design.
- Beta opportunity: `agent.session_open` gains `labels` and `title`, so env injection could be targeted per agent. That is an option, not a replacement for anything today. `env` injection itself is unchanged, so no break expected on upgrade.
- `translations` support exists now; only relevant if you want a zh-CN listing.

**spacedock-bridge**
- It already uses `addScreen`, `addSidebarHeaderItem`, `SidebarRow` from `client/ui`. Fine.
- One deprecation hit: `addWorkspacePanel({ context: "workspace" })`. Still works; dropping the `context` line is a one-line cleanup. Its panel component reads only `theme`, `layout`, `navigation`, so the deprecated `context`/`agentId` props do not touch it.
- `agent.turn_ended` is used only to capture the `paseo` handle, not the `timeline`, so the empty-timeline change does not affect it.
- Opportunities: `useTabState` could keep the panel's selected first officer or filter across reloads; `addAgentPanel` could show a panel tied to one agent; in the beta, `defineAgentTool` could hand a tool to first-officer agents (for example report status) without a separate MCP server. All are optional.

## Raising `requirements.paseo`

Both manifests say `>=0.12.0`. Keep it unless you adopt a 0.13-only API (`useTabState`, `addAgentPanel`, `Markdown`), then use `>=0.13.0`. Beta-only APIs (`defineAgentTool`, `session_open` tools) would need an explicit 0.14 beta range; do not adopt them until 0.14.0 is stable.
